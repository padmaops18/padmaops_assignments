1. Explain the branching strategy we use to keep our main codebase safe.
   We follow the Trunk-Based Development branching strategy to keep our main codebase stable and make sure that all code changes are properly reviewed and tested before they are merged.
   In this approach, we maintain one central branch called main/trunk. So, developers integrate their code changes directly into this main branch. A developer creates a short-lived feature branch from the latest main branch. They clone that Repo to their local, work on their changes locally, test them and push the code to the remote feature branch. Then, they raise a Pull Request (PR) to merge their changes into main. The PR goes through peer code review and as a part of that CI pipeline automatically runs the build, unit tests, code-quality checks using SonarQube and security scans. We also keep branch protection rules so that developers cannot push directly to main branch. Once the PR is successful, code changes are merged into the main branch. Since developers integrate their changes into main branch frequently and in small increments, this helps us to identify integration issues early and avoid large merge conflicts.
